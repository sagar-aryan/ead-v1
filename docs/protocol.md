# Device Protocol (schema 1)

Wire protocol between the EAD-V1 device and host software (dashboard, `tools/eadprobe.py`).
The frame header and message type numbers are fixed by
`ead_agent_docs_v2/08_WIRELESS_PROTOCOL.md`; this document defines everything doc 08
leaves open: payload layouts, sequence semantics, backfill, and the USB framing (DEC-005).

Implementations:
- Firmware: `firmware/lib/ead_core/src/ead/protocol.{h,cpp}`, `firmware/src/link.cpp`.
- Independent host decoder: `tools/eadprobe.py`.
- Golden vectors: `protocol/vectors/*.hex`, generated by `protocol/vectors/generate.py`
  from this document and `CONFIG_V1.json`. Every implementation must reproduce them.

All integers are little-endian. `f32` is IEEE-754 single precision. `str8` is a `u8`
byte count followed by that many UTF-8 bytes (no terminator).

## 1. Versioning

| Field | Where | Value | Changes when |
|---|---|---|---|
| `protocol_version` | Every header | 1 | The header layout changes (doc 08) |
| `schema` | HELLO payload | 1 | Any payload layout or enumeration changes |
| `config_format` | CONFIG_GET payload | 1 | The configuration section layout changes |

A host must compare `schema` in the device HELLO and refuse to interpret payloads of an
unknown schema.

## 2. Transports

### 2.1 Wi-Fi (primary, doc 08)
- Access point SSID `EAD-V1-XXXX` (last two MAC bytes, hex), WPA2. The passphrase is
  generated at first build into `firmware/include/ead_secrets.h` (not tracked).
- Channel 6, device IP `192.168.4.1`, WebSocket `ws://192.168.4.1:8080/ws`.
- One protocol message per binary WebSocket frame. Text frames are ignored.
- One client at a time: a new connection replaces the previous one.
- The device closes a client that has sent nothing for 10 s.

### 2.2 USB (bench fallback, DEC-005)
- Native USB Serial/JTAG, VID:PID `303a:1001`; the USB serial number is the device MAC.
- Each message is framed as `00 | COBS(message ‖ CRC32-LE(message)) | 00`.
  - CRC-32 is IEEE 802.3 (zlib `crc32`).
  - COBS follows Cheshire & Baker. The encoder may emit a trailing `01` block after an
    exact 254-byte run, and decoders must accept either form.
- A receiver discards every byte run between delimiters that fails COBS, CRC or header
  validation. This also skips ROM and bootloader text printed after a reset.
- **Host rule:** open the port without clearing DTR/RTS. Linux asserts both on open, and
  clearing them one at a time passes through DTR=0/RTS=1, which the ESP32-S3 treats as a
  reset request (PROB-005). pyserial: set `dtr = rts = True` before `open()`.

## 3. Header (doc 08 §2, 20 bytes)

| Offset | Type | Field |
|---:|---|---|
| 0 | u16 | `protocol_version` = 1 |
| 2 | u8 | `message_type` |
| 3 | u8 | `flags` = 0 (reserved) |
| 4 | u32 | `payload_length` (must equal message length − 20) |
| 8 | u32 | `sequence` |
| 12 | u64 | `device_time_us` |

### Sequence numbers
- **Device → host, durable messages** (RAW_SAMPLE_BATCH, and later EVENT_BATCH and
  STEP_BATCH): a counter starting at 1 each boot, incremented once per durable message.
  Durable messages are kept in the device ring buffer and can be backfilled.
- **Device → host, all other messages:** carry the latest durable sequence number (0 if
  none yet), so a host notices lost tail data even when only STATUS arrives.
- **Host → device:** a host-chosen command sequence (non-zero, incrementing), echoed in
  ERROR (and later ACK) as `cmd_seq`.

### Time
`device_time_us` is the ESP32 monotonic clock (µs since boot). For RAW_SAMPLE_BATCH it is
the timestamp of the batch's first frame; for other device messages, the time the message
was built; host messages send 0. Host time is never substituted for device time (doc 08 §6).

## 4. Message catalogue (schema 1)

| Type | Name | Direction | Schema 1 behaviour |
|---:|---|---|---|
| 0x01 | HELLO | both | Host identifies; device replies with identity and starts streaming |
| 0x02 | CONFIG_GET | both | Host request (empty); device reply with configuration |
| 0x03 | CONFIG_SET | host → device | ERROR NotSupported |
| 0x04 | SESSION_START | host → device | ERROR NotSupported |
| 0x05 | SESSION_STOP | host → device | ERROR NotSupported |
| 0x06 | PAUSE | host → device | ERROR NotSupported |
| 0x07 | RESUME | host → device | ERROR NotSupported |
| 0x08 | RAW_SAMPLE_BATCH | device → host | Durable; up to 10 frames |
| 0x09 | EVENT_BATCH | device → host | Not emitted |
| 0x0A | STEP_BATCH | device → host | Not emitted |
| 0x0B | HAPTIC_BATCH | device → host | Never emitted (no haptics, DEC-006) |
| 0x0C | STATUS | both | Device status at 5 Hz; host keepalive (empty) at 1 Hz |
| 0x0D | ACK | device → host | Not emitted |
| 0x0E | ERROR | device → host | Reply to a failed command, or `cmd_seq` 0 if unsolicited |
| 0x0F | RECOVERY_INFO | device → host | Not emitted (no flash storage) |
| 0x10 | BACKFILL_REQUEST | host → device | Request stored durable messages |
| 0x11 | BACKFILL_DATA | device → host | Chunks of stored durable messages |
| 0x12 | SERVICE_TEST | host → device | ERROR NotSupported (no haptics) |

Session control arrives with calibration and gait processing (milestones M3–M5) as a new
schema version.

## 5. Payloads

### 5.1 HELLO, host → device (2 bytes)

| Offset | Type | Field |
|---:|---|---|
| 0 | u16 | `schema` the host implements |

### 5.2 HELLO, device → host (57 bytes + firmware string)

| Offset | Type | Field |
|---:|---|---|
| 0 | u16 | `schema` = 1 |
| 2 | u8 | `device_state` (§6.1) |
| 3 | u8 | `reset_reason` (ESP-IDF `esp_reset_reason_t`) |
| 4 | u32 | `boot_id`, random per boot. A change means sequence numbers restarted |
| 8 | u8[6] | `mac` |
| 14 | u8 | `who_foot` (0x70 MPU6500, 0x68 MPU6050, 0 no answer) |
| 15 | u8 | `who_shank` |
| 16 | u8 | `capabilities` (§6.4) |
| 17 | u8[32] | `config_sha256`: SHA-256 of the CONFIG_GET section (§5.5) |
| 49 | u32 | `oldest_seq` stored (0 if empty) |
| 53 | u32 | `last_seq` stored (0 if none) |
| 57 | str8 | `fw_version`, e.g. `0.1.0+c98e010` (`.dirty` = built from uncommitted firmware) |

If the host `schema` differs, the device still replies with HELLO, followed by ERROR
SchemaMismatch.

### 5.3 STATUS
Host → device: empty payload, sent at least once per second while connected. Any valid
host message counts as activity. A link streams only while the host has been active
within 3 s.

Device → host (46 bytes), every 200 ms while streaming:

| Offset | Type | Field |
|---:|---|---|
| 0 | u8 | `device_state` (§6.1) |
| 1 | u8 | `link_flags` (§6.3) |
| 2 | u16 | `faults` (§6.2) |
| 4 | u32 | `frame_index` of the latest frame |
| 8 | u32 | `frames_dropped`: data-ready interrupts not turned into frames, plus frame-queue overflows |
| 12 | u32 | `shank_repeated`: frames whose shank sample was not new |
| 16 | u32 | `i2c_errors`: failed sensor reads |
| 20 | u32 | `imu_reinits`: IMU reconfigurations after a detected power loss |
| 24 | u32 | `oldest_seq` |
| 28 | u32 | `last_seq` |
| 32 | i8 | `ap_rssi_dbm`: strongest connected station, 0 if none |
| 33 | u8 | `ap_stations` |
| 34 | u32 | `heap_free_min`: lowest free internal heap since boot, bytes |
| 38 | u16 | `stack_free_acquisition`: task stack high-water mark, bytes |
| 40 | u16 | `stack_free_processing` |
| 42 | u16 | `stack_free_usb` |
| 44 | u16 | `stack_free_wifi` (0 until a Wi-Fi client has been served) |

Counters are cumulative since boot.

### 5.4 RAW_SAMPLE_BATCH (durable)

| Offset | Type | Field |
|---:|---|---|
| 0 | u8 | `count` (1–10) |
| 1 | u8 | `record_size` = 54 |
| 2 | frame × count | Frames in acquisition order |

Frame (54 bytes, doc 09 §6):

| Offset | Type | Field |
|---:|---|---|
| 0 | u64 | `timestamp_us`: foot data-ready interrupt time |
| 8 | u32 | `frame_index`: foot data-ready count since acquisition start (a gap = lost frames) |
| 12 | i16 × 6 | Foot `ax, ay, az, gx, gy, gz`, chip-frame ADC counts |
| 24 | i16 × 6 | Shank `ax, ay, az, gx, gy, gz`, chip-frame ADC counts |
| 36 | i16 × 4 | Foot quaternion `w, x, y, z`, Q15 |
| 44 | i16 × 4 | Shank quaternion `w, x, y, z`, Q15 |
| 52 | u16 | `status_flags` |

Notes on the frame:
- Doc 09 declares the sensor fields `u16`; they carry the int16 two's-complement pattern
  and are signed everywhere (DEC-007).
- Physical units use the CONFIG_GET values: `accel_g = counts / accel_lsb_per_g`,
  `gyro_dps = counts / gyro_lsb_per_dps`, then the sensor's mount map for anatomical axes.
- In schema 1 the quaternions are identity (`32767, 0, 0, 0`); orientation is not yet
  estimated.

`status_flags`:

| Bit | Name | Meaning |
|---:|---|---|
| 0 | `foot_read_fail` | Foot I²C read failed; foot values are 0 |
| 1 | `shank_read_fail` | Shank I²C read failed; shank values are 0 |
| 2 | `shank_repeated` | Shank data-ready flag was clear: same sample as the previous frame |
| 3 | `foot_accel_saturated` | A foot accel axis at ±full scale |
| 4 | `foot_gyro_saturated` | A foot gyro axis at ±full scale |
| 5 | `shank_accel_saturated` | A shank accel axis at ±full scale |
| 6 | `shank_gyro_saturated` | A shank gyro axis at ±full scale |
| 7 | `foot_repeated` | Foot data-ready flag was clear (not expected: frames are foot-clocked) |
| 8–15 | reserved | 0 |

The two IMUs run on independent clocks (measured 0.14 % apart, TEST-015). The shank
therefore occasionally repeats a sample, and bit 2 marks it.

### 5.5 CONFIG_GET
Host → device: empty. Device → host:

| Offset | Type | Field |
|---:|---|---|
| 0 | u16 | `config_format` = 1 |
| 2 | u8[32] | SHA-256 of the section |
| 34 | u16 | `section_length` |
| 36 | u8[] | Section |

Section format 1 (188 bytes). Fields in order, no padding. Values come from
`include/config_v1.h` and must equal `CONFIG_V1.json` (enforced by the
`config_section.hex` vector).

| Group | Fields |
|---|---|
| IMU | u8 foot_addr, u8 shank_addr, u32 i2c_hz, u16 sample_hz, u8 accel_range_g, u16 gyro_range_dps, u8 dlpf_hz, u8 dlpf_cfg, u8 smplrt_div, f32 accel_lsb_per_g, f32 gyro_lsb_per_dps |
| Mount maps | i8×9 foot mount, i8×9 shank mount (row-major, anat = M · chip) |
| Pins | u8 sda, u8 scl, u8 foot_int, u8 shank_int, u8×6 motor M1–M6 |
| Calibration | u8 static_s, f32 mahony_kp, f32 mahony_ki |
| Gait | f32 gait_lowpass_hz, f32 event_lowpass_hz, f32 min_cycle_s, f32 max_cycle_s, u16 contact_guard_ms, u16 toeoff_guard_ms, u16 ic_window_ms |
| ZUPT | f32 accel_tol_g, f32 gyro_dps, u16 min_ms, u16 entry_hyst_ms |
| Error engine | f32 class_activation, f32 haptic_on, f32 haptic_off, f32 confidence_haptic, f32 robust_z_clip, f32×7 weights (swing dorsiflexion, IC plantarflexion, inversion/eversion, timing, stance/swing ratio, cycle distance, shank dynamics) |
| Haptics | u8 haptics_fitted, u16 pwm_hz, u8 pwm_bits, u8 min_duty, u8 max_duty, f32 intensity_exponent, u8 max_on_s, u8 rolling_window_s, f32 rolling_duty_limit, u16×6 motor positions (deg) |
| Network | u8×4 AP IP, u16 WebSocket port, u8 frames per raw batch |
| Storage | u16 block_bytes, u16 flush_ms, f32 free_space_floor |
| Reference | u16 minimum_valid_cycles, u16 reference_check_cycles |

The SHA-256 is the configuration hash that doc 18 requires with every session.

### 5.6 ERROR (device → host)

| Offset | Type | Field |
|---:|---|---|
| 0 | u32 | `cmd_seq` of the failed command, 0 if unsolicited |
| 4 | u8 | `cmd_type`, 0 if unsolicited |
| 5 | u16 | `code` |
| 7 | str8 | `detail`, human-readable |

| Code | Name | Meaning |
|---:|---|---|
| 1 | BadFrame | Header invalid or length mismatch |
| 2 | SchemaMismatch | Host HELLO schema differs from the device schema |
| 3 | NotSupported | Message type not supported by this schema |
| 4 | InvalidState | Command not allowed in the current device state |
| 5 | BadPayload | Payload length or content invalid |
| 6 | BackfillUnavailable | Part or all of a requested range is no longer stored; `detail` names the range served |

### 5.7 BACKFILL_REQUEST (host → device, 8 bytes)

| Offset | Type | Field |
|---:|---|---|
| 0 | u32 | `first_seq` (≥ 1) |
| 4 | u32 | `last_seq` (≥ `first_seq`), inclusive |

### 5.8 BACKFILL_DATA (device → host)

| Offset | Type | Field |
|---:|---|---|
| 0 | u32 | `cmd_seq` of the request |
| 4 | u32 | `first_seq` in this chunk |
| 8 | u32 | `last_seq` in this chunk |
| 12 | u8 | `more`: 1 when further chunks follow for this request |
| 13 | … | The stored durable messages, complete (header + payload), concatenated |

Each BACKFILL_DATA message is at most 2800 bytes. That is the largest message lwIP
accepts without blocking (§7). If messages are evicted while a request is being served,
the next chunk starts at the oldest stored sequence.

## 6. Enumerations

### 6.1 Device state (doc 07 §6)
`0 BOOT, 1 SELF_TEST, 2 CALIBRATING, 3 REFERENCE_CAPTURE, 4 READY, 5 RUNNING, 6 PAUSED,
7 FAULT, 8 RECOVERY`. Schema 1 reports SELF_TEST until boot completes, then READY while no
fault bit is set, otherwise FAULT.

### 6.2 Fault bits

| Bit | Name | Set when | Cleared when |
|---:|---|---|---|
| 0 | foot_absent | No valid WHO_AM_I at boot or reinit | Successful reinit |
| 1 | shank_absent | Same, shank | Successful reinit |
| 2 | foot_config | Register readback mismatch | Successful reinit |
| 3 | shank_config | Same, shank | Successful reinit |
| 4 | foot_no_data_ready | < 20 foot data-ready pulses in the 250 ms self-test | Reboot |
| 5 | shank_no_data_ready | Same, shank | Reboot |
| 6 | no_psram | Ring fell back to 64 KB internal RAM | Reboot |
| 7 | foot_frozen | 50 consecutive identical foot samples | Next changed sample |
| 8 | shank_frozen | Same, shank | Next changed sample |
| 9 | acquisition_stalled | No foot data-ready for 30 ms | Next data-ready |

### 6.3 Link flags
Bit 0 `usb_active`, bit 1 `wifi_active`: a host on that link sent HELLO and has been
active within 3 s.

### 6.4 Capabilities
Bit 0 `haptics_fitted`, bit 1 `flash_storage`, bit 2 `psram_ring`.

## 7. Streaming and backfill

1. Host connects and sends HELLO.
2. The device replies with HELLO and starts that link's cursor at `last_seq + 1`. It then
   streams STATUS every 200 ms and every new durable message in sequence order.
3. The host sends STATUS keepalives at least once per second.
4. **Lost messages.** The host tracks the highest durable sequence received.
   - A jump from `n` to `m > n + 1` means `n+1 … m−1` were lost; the host sends
     BACKFILL_REQUEST for that range.
   - After a reconnect, the host requests `last_received + 1 … last_seq` from the new HELLO.
5. **Reboots.** When the HELLO `boot_id` changes, the device rebooted: sequence numbers
   restarted and nothing from the previous boot can be backfilled.
6. **Priority.** Per link: pending replies, then STATUS when due, then live durable
   messages, then backfill chunks.

Retention and flow control:
- **Ring size.** The ring is 4 MB of PSRAM, about 12 minutes of raw batches (5.6 kB/s).
  Messages evicted before a link sends them are skipped; the host sees the gap.
- **Wi-Fi.** A link writes only when the socket reports writable. lwIP does that only
  with more than 2880 bytes of its 5760-byte send buffer free, and no message exceeds
  2800 bytes, so the device never blocks on a slow client.
- **USB.** A frame is written only when the CDC transmit buffer (16 KB) can take it whole.
